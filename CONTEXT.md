# Academic Guardrail Context

This project provides citation metadata lookup, source-backed retraction alerts, local reference matching and source-linked client review through CLI and one MCP server.

## Boundaries

- Reference entry points call AuditService; raw-text review packets explicitly skip identity verification.
- Providers collect facts. `core/reference_decision.py` assigns reference status. `ClaimEvaluator` optionally adds heuristic text comparison.
- Identity ambiguity takes precedence over retraction. Confirmed same-DOI evidence is retained across sources; title keywords alone remain suspected.
- `RetractionStatus` has CONFIRMED, SUSPECTED, NO_RECORD and NOT_CHECKED. Neither of the latter means a paper is normal.
- `EvidenceSource` records source, kind, identifier, detail and an optional source flag. A final verdict and a source observation are separate concepts.
- `REFERENCE_METADATA`, `TEXT_RETRIEVAL` and `RULE_BASED_REVIEW` describe different scopes. Alignment scores and labels are not calibrated entailment judgments.
- Offline mode does not initialize online providers or embedding models. `--refs-dir` alone does not enable offline mode.
- The built-in retraction index has three historical demo records. It is not complete or automatically synchronized.
- The client model supplies semantic conclusions. `prepare_claim_review` / `read_claim_evidence` / `record_claim_review` preserve source evidence, check its digest and exact quotes, and append records. `EVIDENCE_LINKS_VALID` is mechanical validation, never semantic certification. There is no server-side model API.
- Local follow-up adds three tools to the same server (ten total): `prepare_local_claim_review`, `follow_up_local_claim`, `generate_claim_review_report`. A recorded unresolved judgment can supply a bounded `missing_evidence` gap for one literal lookup in the same unchanged local source. Original evidence and record IDs remain intact. Separate checked context files bind the source and parent review while preserving legacy packet v1 serialization. HTML reports compare saved judgments and show current source status; the client still supplies every semantic conclusion. Read `docs/local_followup_guide.md` before changing this workflow.
- Evidence coverage is a client declaration, not proof that a model considered every sentence. Local reference extraction can already have truncated source units. Legacy HTML remains rule-only; client results are saved separately.

## Development

Read `docs/learning_guide.md`, `docs/phase_two_guide.md` and `docs/plans/phase_two.md`. Preserve simple module responsibilities and explicit failure states. Unit tests block external HTTP, isolate caches and disable model downloads. Do not represent unit tests, synthetic fixtures or historical prediction files as current live-provider or LLM benchmark results.

Phase two separates bibliography entries from occurrences, reuses reference decisions, preserves parsing diagnostics and retrieves local body passages with exact file/page/character positions. Known DOI targets require corresponding local DOI identity. Uncited entries are metadata-only. Retrieval status remains separate from identity/retraction status; failed upstream queries are retained alongside successful local fallbacks.

Phase three adds inspectable number, negation, causality and scope rules; phase four separates evaluation inputs, labels, predictions and scoring. Read `docs/client_review_guide.md` and `docs/semantic_coverage_results.md` for the client workflow and current evidence boundaries. Rules remain unresolved on all 339 SciFact dev pairs after the context fixes. The separate 12-pair public-train interactive pilot is not a general benchmark or evidence of improvement over a bare model.

`docs/client_evaluation_results.md` adds 60 balanced public-train cases: discovery 30/36 agreement, later validation 18/24. The judging client is the current Codex conversation, underlying model ID unknown; no model is trained or called inside the server. `SuggestedRevision` is optional source-linked drafting help, mechanically checked but never counted as verification of the original claim. The vs. sentence-boundary bug is fixed; general semantic gains remain unproven. Preserve the frozen wrong predictions and gold labels.

`docs/paired_review_results.md` records the subsequent 30-case, 90-judgment comparison using independent Codex CLI contexts requesting `gpt-6.1-sol`, high reasoning. Direct / guided direct / MCP label agreement is 22/30, 21/30, 21/30; CONTRADICT recall is 9/10, 8/10, 8/10. MCP wins two and loses three cases against direct; no semantic uplift or human-time saving is established. All 271 quoted passages are exact. The 12 direct storage rejections are missing cross-field quote links under unequally explicit v1 instructions, not fabricated quotes or factual errors. Optional `ClaimFinding` checks client-declared consistency and always keeps `findings_semantically_verified=false`. The future v2 protocol gives all arms the same explicit storage rules and is unmeasured; preserve all v1 outputs and score against unchanged gold. See `docs/paired_review_guide.md` for reproduction and module responsibilities.

`docs/local_followup_results.md` records the later `local_evidence_followup_v1` comparison at clean code commit `7108a4be`: five real papers, 15 assistant-authored/perturbed claims, development 9 and different-paper validation 6, both plans frozen before judgments. Shared abstract judgments all remain NEI; both local follow-up and direct parsed-main-text reading reach 15/15 full-text label agreement, 10/15 correct concrete verdicts, five remaining NEI, and zero false concrete verdicts. There is no paired semantic gain. Both paths use 30 effective calls including the shared initial 15; actual execution is 45 independent CLI contexts requesting gpt-6.1-sol/high. Input tokens are 527441 direct vs 379351 local (-28.08%); output 39474 vs 25211; reasoning output 6326 vs 6633, so not every usage category falls. All 91 quotes are exact. The texts have prepared metadata and an abstract copy, stop at References, and omit later appendices. Do not infer natural-benchmark/general accuracy, human-time savings, arbitrary PDF coverage, or improvement over the earlier SciFact scores. Frozen raw data stays under the local 20261110 audit directory; the scorer checks source/code/packet/prompt/request hashes before reading partition gold. The 15-chain HTML report preserves 30 actual MCP review records.

Complex layout/OCR, arbitrary citation styles/TeX macros, general semantic accuracy and online coverage remain limitations. `scripts/validate_phase_two.py`, `validate_phase_three.py`, `validate_client_review.py` and `validate_local_followup.py` use synthetic scripted fixtures with HTTP/model guards; those runs are engineering evidence, not model-accuracy experiments.
