# 90 条真实来源样本：本地补查节省了什么，又遗漏了什么

记录日期：2026-11-18。客户端请求固定为 `gpt-6.1-terra`、推理 `max`，协议为 `local_evidence_followup_v3`。本次完成 15 篇论文、90 条论断的四种流程对照，代码与材料在调用前冻结。项目仍是一个 MCP 服务，四种流程不是四个 MCP 服务。

## 实际结论

**本地补查减少了输入和输出 token，但未保持单次阅读全文的判断完整性。** 相比一次读取全部可解析正文，本地补查输入 token 少 26.11%，输出少 19.48%；原始反驳召回从 45/45 降为 40/45。它留下了 7 条可避免的证据不足和 1 条不确定，另有一条正确的反驳因证据编号声明不完整而未能保存。因此，这轮支持“以部分漏检换取上下文减少”，不能支持“比直接使用大模型更准确”。

“真实来源”指原始论文真实、版本和坐标可核对。90 条论断与参考标签由材料助手依据论文编写或扰动，并经另一助手复核；它们不是自然用户问题，也不是独立人类专家 gold。下表的正确性均指与这组冻结参考标签一致。

单次全文主对照没有先前答案；两阶段全文接收共同摘要初判；本地流程只对已保存且说明缺口的未决初判补查一次，已明确的 28 条沿用初判。四种流程使用相同语义说明、结构化输出和共同校验器，全文对照也使用相同解析器提供的编号原文。这里比较的是选文流程，不是未经约束的聊天界面，也没有测试直接上传任意 PDF 的体验。

摘要初判只获得摘要，不能要求它回答正文才有的内容。摘要专用标签一致率为 88/90；这不等于解决了 88 条完整问题。上表为了说明补查的实际增量，反驳召回和可避免 NEI 使用全文参考标签；通用 JSON 汇总中，摘要臂的 recall/avoidable NEI 默认使用摘要参考标签，二者分母不同。

本地流程将可用的正确明确判断从 28 条增加到 66 条，但一次全文已取得 75 条。剩余 24 条包括 15 条参考证据不足、8 条有答案却未解决，以及 1 条正确答案未通过保存校验。不能把全部未决样本解释为论文缺乏证据，也不能为了减少未决数量而强行给出支持或反驳。

三条最终流程都把 15 条参考 NEI 保留为 NEI。两个全文对照原始标签均为 90/90；本地补查为 82/90，考虑输出有效性后为 81/90。逐例主比较为本地补查 **0 胜、8 负、82 同对、0 同错**，次比较相同。这个选定材料上的高分不是通用准确率，也不证明模型未在训练时见过这些著名论文。

## 漏掉的是什么

全部八条原始标签差异都发生在正文可答样本。它们的补查包没有包含预先标注的决定性文本；不能笼统解释为“模型过于保守”。这里的模型是评测脚本单独调用的 terra/max 客户端，MCP 负责检索、绑定和校验，项目没有训练或修改模型权重。

| 样本 | 完整论断的关键要求 | 补查实际缺少什么 | 原始结果 |
| --- | --- | --- | --- |
| `development_albert_03` | ALBERT 的 Table 1 同时列出 12M 参数、128 维嵌入 | 找到其他表的相同数值，却没有 Table 1 本身 | NEI，参考为支持 |
| `development_electra_05` | 下游微调是否同时保留生成器和判别器 | 返回联合预训练与训练方案，漏掉丢弃生成器的正文 | NEI，参考为反驳 |
| `development_bart_04` | 文档旋转是否始终保留原首 token | 返回一般噪声机制，漏掉随机选择新起点的定义 | NEI，参考为反驳 |
| `validation_a_swin_05` | 注意力是否省略相对位置偏置 | 返回窗口注意力介绍，漏掉偏置计算说明 | NEI，参考为反驳 |
| `validation_a_simclr_03` | 默认投影头是否输出 128 维 | 返回消融图和其他维度配置，漏掉默认配置段 | NEI，参考为支持 |
| `validation_a_simclr_04` | 默认批量是否为 256，训练是否为 100 epochs | 返回批量范围和吞吐脚注，漏掉默认批量说明 | NEI，参考为反驳 |
| `validation_b_convnext_03` | 每个块是否采用 7×7 depthwise conv | 返回线性化结构图，缺少直接解释该选择的正文 | UNCERTAIN，参考为支持 |
| `validation_b_convnext_05` | 最终残差块是否采用 BatchNorm | 返回一般模型介绍，漏掉选择 LayerNorm 的段落 | NEI，参考为反驳 |

当前检索在同一论文内使用字面短语，按“不同词命中数 → 总出现次数 → 原文顺序”排序，选择前三段及相邻上下文。PDF 断行、连字符、连字，以及常见方法名称抢占排名都会影响命中。只增加一段候选也不能解决所有遗漏，应先检查查询与目标段的实际匹配和排名。

不改动规则的离线回放显示，ELECTRA、Swin、SimCLR 默认批量三条关键段都排第 4；ALBERT 为第 9，SimCLR 投影维度为第 14，BART 为第 18，ConvNeXt 归一化为第 23，ConvNeXt 卷积尺寸为第 32。它们实际均未进入补查包。该诊断没有新增模型调用，也不证明把上限改成四段就能取得经过实测的新分数。

另一个独立问题是 `validation_a_simclr_05`：模型正确反驳“BN 统计只在单设备聚合”，引用也逐字有效，但只声明考虑了 91 个证据单元中的 90 个，漏掉 `e91`。共同校验器与 MCP 保存流程都拒绝它。这证明字段声明不完整，不证明模型从未读过该段。原始正确答案仍计入原始指标，不能计入可用结论；报告保留此前已保存的判断。

独立复算逐项比对了指标和用量，未发现数值差异。来源复核核对了 90 个最终本地证据包的 **4,908 个证据单元实例**与 **287 处引文**，均能逐字对应到保存的提取文本和 PDF 页映射；这些实例包含跨样本重复内容，不是 4,908 条独立科学证据。全部八条差异、被拒输出和六条未覆盖单一参考锚句的正确明确判断另作逐例审查；那六条有其他充分文本，因此“锚句没命中”本身不能作为语义失败指标。这是助手的非盲复核，不是人类专家认证，也不意味着逐字校验能认证科学推理。

## 执行、修复与可复现边界

本次新增独立单次全文主对照、严格的跨批次汇总、跨批次会话去重和实际导入包核验。核心只修复摘要边界解析：PDF 折行中的普通 results/methods 等词不能被当作标题截断摘要；真正带编号的章节标题可以有副标题。中文代码阅读顺序见[评测导读](local_followup_evaluation_guide.md)。服务端没有新增模型 API。
