# 同证据直接模型对照：结果与反驳召回诊断

记录日期：2026-11-01。本轮完成 30 个新样本、三组共 90 次独立客户端判断。

**本轮没有测出 MCP 相对直接模型的反驳召回或总体标签一致率提升。** MCP 输出更少错误的支持/反驳，也把更多原本可判定的样本留为证据不足。这是本次小样本中的取舍，不能概括成普遍更准或已节省人工。

## 1. 测了什么

- 请求模型为已登录 Codex CLI 的 `gpt-6.1-sol`，推理 `high`；CLI 版本 `0.166.0-alpha.5.1`。每个样本每组建立新临时会话。具体后台模型快照及采样温度未提供，不推断这些值。MCP 服务本身没有内置模型，也没有训练模型。
- 固定官方 SciFact archive，SHA-256 `11c621288d41ac144d29b13b0f8503b3820b7d6e8b1f6ff24dff335c196d76be`。从公开 train 按三类等量选 30 对，每类 10；排除既有 72 对的 claim/document IDs。新旧之间及新组内无完全相同摘要。ID/文献隔离不保证语义概念完全独立。
- 三组的论断、完整摘要证据单元、编号、顺序和 JSON 格式一致。`direct` 使用简短判断说明；`guided_direct` 增加项目语义提示；`mcp` 在同样提示上加入实际 MCP 的规则/检索提示，并通过 MCP 保存判断。直接组也是结构化输出客户端，不是无系统指令的裸模型 API。
- 各组每例一次 CLI 调用，无运行器重试或纠错。三组同时最多并行三个调用，按案例轮换启动顺序。90 份提示在判断前冻结，全部答案保存并生成 completed manifest 后才打开 gold。CLI 内部传输可能重试，一次调用不等于可确认的一次 HTTP 请求。
- 实际存在 90 个不同会话、90 个完成回合，未观察到工具调用或无法解析的事件。请求关闭记忆/工具/技能等，但本机诊断仍可见工具定义及技能元数据；这不是工具完全不可用的证明。诊断未见历史评测结果或记忆标记，也不是后台请求的完整捕获。

本轮语义逻辑固定在 `83254c4`，正式运行前只修复失败时停止的逻辑，最终运行代码为 `adeaa9a`。计划 `plan_v2` 与先前计划的全部 90 份提示、共同 schema、数据和 gold 哈希相同。这里的目录名 `plan_v2` 是运行计划修订号；**实测协议仍是 `paired_source_review_v1`**。

冻结数据 manifest 的 `source.name` 误继承了通用来源文件中的 dev 显示名；`split=train`、实际读取路径、30 条输入及 gold 均独立核对为 train。保留原 manifest 及哈希，仅修正后续生成器的显示名，未替换样本。

## 2. 原始判断结果

| 指标 | 直接模型 | 相同模型 + 语义提示 | 相同模型 + MCP |
| --- | ---: | ---: | ---: |
| 与原 gold 一致 | 22/30 = 73.33% | 21/30 = 70.00% | 21/30 = 70.00% |
| 反驳召回 | 9/10 = 90% | 8/10 = 80% | 8/10 = 80% |
| 反驳精确率 | 9/10 = 90% | 8/9 = 88.89% | 8/8 = 100% |
| 支持召回 | 5/10 | 4/10 | 3/10 |
| NEI 召回 | 8/10 | 9/10 | 10/10 |
| 明确支持/反驳的数量 | 16/30 | 13/30 | 11/30 |
| 上述明确判断中符合 gold | 14/16 | 12/13 | 11/11 |
| 输出证据不足（NEI） | 14/30 | 17/30 | 19/30 |
| 弃判 / 执行错误 | 0 / 0 | 0 / 0 | 0 / 0 |

MCP 的 19 条 NEI 中有 9 条官方标签是 SUPPORT 或 CONTRADICT，不能把它们计为完成核验。也不能用当前 8/10 与上一轮不同样本、未知精确模型配置的 3/8 相减，声称反驳召回提高 42.5 个百分点。

配对观察：

- **MCP 对直接组：多对 2 条、少对 3 条、25 条正确性相同，净少对 1 条。** 两处改善都是将错误的明确判断转为 gold NEI；三处损失也都是转为 NEI。
- **MCP 对提示组：多对 1 条、少对 1 条，净变化为零。** 不能把提示组已有的改善再归功于 MCP 提示包或传输。
- 三项探索性精确 McNemar 双侧 p 值均为 1.0。这不证明各方法等效，只说明本样本不足以支持差异。反驳召回的描述性 Wilson 95% 区间分别约为 59.6%–98.2%、49.0%–94.3%、49.0%–94.3%；仅有 10 个反驳标签，区间很宽。

## 4. 引用与记录能力：不能冒充语义增益

原文引用由模型直接生成，未由 helper 按 ID 代抄。直接组 **67/67**、提示组 **98/98**、MCP 组 **104/104** 均逐字匹配，共 271/271。没有观察到某一组在本批引文真实性上优于其他组。

相同离线记录检查器接受直接组 18/30、提示组 30/30、MCP 组 30/30。直接组 12 次拒绝全部是 findings 的某些证据 ID 没有对应的 quotes，**不是 12 条伪造引用**，且其中 9 条标签正确、3 条标签错误。接受后的直接组标签一致率为 13/18，不能用删掉拒绝项的分母替代原始 22/30。

这个次要指标还有协议限制：v1 简短直接提示未同等明确列出每条跨字段规则。接受率差距反映了提示对项目记录规范的说明程度，不能证明 MCP 发现或纠正更多事实错误。MCP 组实际通过 stdio 保存了 30 条结果，记录、快照和返回值一致；这验证了记录流程，没有认证语义。

已发布的后续 **`paired_source_review_v2`** 把完整存储契约写入三组共同提示和 schema 描述；**v2 未运行新的模型评测**。原 v1 90 条判断与分数不变，当前计分代码重放的结果与原指标文件逐字节相同。新一轮必须固定新协议并明确已暴露样本的排除，不能把 v2 说明修改包装成效果提升。
