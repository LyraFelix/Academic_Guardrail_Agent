# 扩大样本后的客户端评测与整改记录

记录日期：2026-11-01。新增 60 个样本，不覆盖上轮 12 个样本及其原始结果。

本次判断由**当前 Codex 对话中的助手**完成。MCP 服务没有内置另一套大模型，也没有调用独立模型 API；具体底层模型 ID、采样配置及 token/费用不可得。修改的是项目证据处理、提示、记录与评测代码，没有训练或修改 Codex 模型权重。

结果没有证明语义准确率提升：发现组 30/36 与标签一致；修改后在另一组 24 条样本上为 18/24。两组样本不同，不能把分数变化归因于提示或分句修改。后续验证组仍漏掉了多数 CONTRADICT 标签，项目当前不能宣传为可靠的全自动事实核验器。

## 1. 样本与流程

- 使用同一官方 SciFact archive：SHA-256 `11c621288d41ac144d29b13b0f8503b3820b7d6e8b1f6ff24dff335c196d76be`。
- 从公开 train 选 36 个发现组配对和 24 个后续验证配对，三类分别为 12/12/12 和 8/8/8。**这次按标签分层**，不是上轮按自然分布抽取的协议。抽样代码明确记录这一点；判断输入不含标签。
- 固定 seed `client-evaluation-v1`，按哈希顺序在各类配额内取样。排除上轮 12 个样本的 claim ID 与 document ID；两组间也不重复论断或文献，每组一个文献只出现一次。它不保证相近研究主题或语义相近论断族完全隔离。
- 输入为完整给定摘要，不包括 gold 或标注句索引。无须联网取全文；这不测真实稿件解析、论文检索、引用身份或撤稿覆盖。
- Codex 读取实际 MCP 证据包后作出结论、理由、引用编号。辅助脚本按已选编号复制原文，保存 JSONL，没有按标签生成答案。引用接受率衡量连接一致性，不能算自由生成引用的正确率。
- 发现组全部冻结并经 MCP 保存后才读取发现组 gold。根据问题修改并固定代码后，才读取验证组输入；验证组判断保存后才读取其 gold。原始结果不回写，不用验证组答案调同轮分数。

原始 `evidence` 标注与 `cited_doc_ids` 的含义参照 [SciFact 官方数据说明](https://github.com/allenai/scifact/blob/master/doc/data.md)。没有证据标注的所引摘要按本项目协议记 NEI；原有标注保持不变。抽样分层、完整摘要输入和客户端标签一致率均不是官方 leaderboard 协议。

## 3. 发现组问题与修改依据

| 配对 | 原判断 / gold | 从给定原文能确认的问题 |
| --- | --- | --- |
| `1193:20532591` | CONTRADICT / NEI | 将“主要 A 而不是 B”读成“B 完全不存在”，用 B 中存在的观察反驳主导比例；这是明确的推理错误。 |
| `1119:18997216` | NEI / SUPPORT | 原文比较中的 `vs.` 被错误切句；但判断正确拼回了数值，实际分歧是“33 周样本”能否支持“整个孕期”，不能把标签分歧归因于切句。 |
| `1327:24241932` | NEI / CONTRADICT | 原文是 overcrowding，论断是区域人口稀疏程度；判定没有直接把两个指标等同。 |
| `942:11527199` | NEI / SUPPORT | 原文提出 HCT 单倍型/LD 的条件性用途，论断写为器官移植匹配预测；涉及适用对象与证据强度。 |
| `499:26064662` | UNCERTAIN / CONTRADICT | “高估血糖控制”可能指高估血糖，也可能指显得控制得更好；两种解释方向不同。 |
| `771:15476777` | NEI / CONTRADICT | 将不同析因比较中的生存和生活质量拼接；差异不显著也不等于疗效等同。 |

这些结果全部按原 gold 计分，不把解释分歧改成“答对”。除明确的比较性否定误读外，其余不能笼统归为“模型过于保守”，也不能因此宣称数据集标错。

对应的仓库修改：

1. **比较句边界。** `sentence_units()` 不再把 `vs.` 当成句末，保持原文位置。发现组实际样本从 16 个错误拆分单元恢复到 9 个单元；数字比较保留在同一证据句内。中文标点、正常句界和小数仍按原规则处理。
2. **客户端比较提示。** 明确相对主导程度与绝对不存在的区别，要求同一指标、比较组、时间和因果方向；不把不显著当等效，也不把一个时间点外推到始终。此处是工作流提示改进，尚未证明提升模型泛化准确率。
3. **有引用的改写建议。** `ClientJudgment.suggested_revision` 可包含更窄的说法、理由和证据 ID。服务端要求完整阅读声明、可用来源以及每个 ID 的逐字引用；不改变原论断结论，不认证改写语义。
4. **评测身份与完整分母。** 保存客户端名称、已知模型 ID 或 null、交互/API 模式和上下文说明；输出三类 precision/recall、逐条结果、NEI 与错误。抽样与来源文件从同一字节快照解析和计算哈希，排除清单也保留副本。

验证组生成 **11 条改写建议**，分别来自 6 条客户端 SUPPORT、3 条 CONTRADICT、2 条 NEI；每条经过证据链接校验。这不是 11 条未解决论断获验证，也没有独立的改写金标准确率。例如，原论断询问 NIV 的预测作用时，可改写为给定论文实际测量的“已发生呼吸衰竭的选定移植患者接受 NIV 后，插管率较低”，并保留人群、对照和原文引用。无相关结果的材料不强行生成改写。

实体映射、摘要缺失和结局/比较对象错位仍是需要继续处理的边界。下一轮应记录哪些实体对应直接出现在原文、哪些来自额外来源，并对缺失的结果请求相应段落或全文；不能仅放宽提示使其迎合本批标签。
